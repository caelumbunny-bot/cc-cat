一、现有同步机制调研结论
------------------------

数据库路径：/root/memory/palace.db
同步脚本路径：/root/memory/sync-twitter.js

entries 表结构：
  id          INTEGER PRIMARY KEY AUTOINCREMENT
  ts          DATETIME DEFAULT CURRENT_TIMESTAMP
  kind        TEXT NOT NULL       -- 'tweet'
  author      TEXT NOT NULL       -- 'bunny-public'
  content     TEXT NOT NULL       -- 推文内容（格式见下）
  tags        TEXT                -- 逗号分隔标签
  mood        TEXT                -- 情绪标注
  source_hash TEXT UNIQUE         -- 去重键，格式：tweet:<tweet_id>

去重机制：UNIQUE INDEX idx_source_hash 配合 INSERT OR IGNORE 实现幂等写入。

数据源：bb-browser CLI（本地 Twitter 自动化工具），命令：
  bb-browser site twitter/tweets bunnyloustin <count> [cursor]

原始脚本（旧）每4小时触发一次，每次只取最近20条，无分页，不标记回复，不处理图片URL。

二、本次改造内容（sync-twitter.js 新版）
-----------------------------------------

改动一：分页抓取
  普通运行：最多3页×20条，遇到已知推文立即停止
  --init 模式：最多10页×100条（用于历史初始化）

改动二：图片/媒体URL提取
  推文文本中包含 https://t.co/xxxxx 的视为潜在媒体URL，
  在 content 中追加一行：
    📸 media: https://t.co/xxxxx
  同时在 tags 中添加 has-media 标签，便于未来批量接入识图API。

改动三：回复标记
  当 t.in_reply_to 字段存在时（Bunny在别人/自己推文下回复），
  在 content 顶部添加：
    [↩ 回复 https://x.com/i/status/<original_tweet_id>]

改动四：自动标签新增 has-media
  原有标签体系保留，新增 has-media 用于标记含媒体的推文。

新版 content 格式示例（含回复+媒体）：
  [↩ 回复 https://x.com/i/status/2050611273239323120]
  狂喜……………… https://t.co/YaR9n5aR5O

  📸 media: https://t.co/YaR9n5aR5O

  —————————
  ❤️ 1 · 🔁 0 · 💬 0
  https://x.com/Bunnyloustin/status/2050613676046991648

三、Cron 配置
--------------

修改前（每4小时）：
  0 */4 * * * /usr/bin/node /root/memory/sync-twitter.js >> /var/log/memory-palace-sync.log 2>&1

修改后（每30分钟）：
  */30 * * * * /usr/bin/node /root/memory/sync-twitter.js >> /var/log/memory-palace-sync.log 2>&1

日志文件：/var/log/memory-palace-sync.log
错误处理：stderr 重定向到同一日志文件（2>&1），脚本内部错误通过 process.exit(1) 中断
  并输出明确错误信息，不会静默失败。

手动触发命令：
  node /root/memory/sync-twitter.js
  node /root/memory/sync-twitter.js --init   # 初次全量导入

六、后续建议
-------------

1. bb-browser 数据新鲜度：若 bb-browser 持续只返回旧数据，
   可尝试重启 twitter-mcp 服务：
     systemctl restart twitter-mcp
   或检查 Twitter API 登录状态。

2. 图片识图：通过 has-media 标签筛选推文，
   对 content 中 "📸 media: " 行的 t.co URL 进行展开后送识图API。

3. 历史补全：如需导入更多历史推文，运行：
   node /root/memory/sync-twitter.js --init
